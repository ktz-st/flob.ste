# File-backed Flob: dynamic resource residency

Build/tool installation: BUILDING.md. AI-agent workflow: AGENTS.md.
Tester instructions: TESTERZY.TXT (canonical copy in flob-ste; included in
the HDD ZIP under flob/TESTERZY.TXT). The user reported a completed playthrough;
comparison by original-A8 players is the next validation step. This does not
replace physical-hardware/media testing of the file-backed edition.

Separate distribution generated from the working embedded-resource port.
The original flob.prg / flob-st.prg and artist assets are not replaced.
Resources now use group-owned GEMDOS allocations instead of permanent BSS
arrays. Only resident resources and the active world/scene/music are loaded.
All resource disk reads occur with the hardware palette black, including
manual music changes during gameplay. Real-hardware and full-playthrough
validation of this distribution remain necessary.

## Build and run

From the original flob-ste directory:

```sh
make files
make files-floppy
python3 verify_floppy.py --no-build
python3 verify_file_version.py --gameplay --lifetime
```

Default output is the sibling directory `flob-files`:

- `disk/FLOB.PRG`: automatic ST/STE renderer selection, PSG audio.
- `disk/FLOBST.PRG`: forced CPU renderer, PSG audio.
- `FLOB720.ST`: standard 720 KiB FAT12 floppy (80 tracks, two sides, nine
  sectors/track), generated by `make files-floppy`. Launch `A:\FLOB.PRG`.
  Only the auto-detect PRG is included; the forced-CPU copy is unnecessary.
  Existing user saves are never copied into the image.
- `disk/COMMON`, `TITLE`, `INTRO`, `OUTRO`, `CREDITS`, `ENDING`, `WORLD0`..`WORLD5`:
  bundles with TOS-compatible 8.3 names.
- `src`: generated build inputs, not a second manually maintained source fork.
  Do not edit these copies; rerunning the exporter replaces them. Canonical
  PNGs and original conversion tools remain in flob-ste.
- `manifest.json`: per-resource source path, symbol, size, offset, SHA256,
  CRC32 and group membership.

Copy the complete `disk` contents, not just the PRG. Launch with that directory
as the working directory (normal GEM launch from the folder). Save behavior and
flob.sav are unchanged; the exporter never copies, deletes or overwrites saves.
Tests now use 1 MB and configured TOS, without overriding the user's TOS image.
Packaging requires `apultra`, `upx` and mtools (`mformat`, `mcopy`, `mmd`).
The PRGs use UPX Atari/TOS compression, verified by `upx -t` after packing.
The generated edition explicitly reserves 64 KiB stack and 64 KiB Pascal heap;
screens and resources use separate GEMDOS allocations. The embedded build is
unchanged. Do not remove this memory budget and rely on FPC's larger defaults.

## Grouping

Group primarily by lifetime, then by kind:

| Group | Files | Purpose |
| --- | --- | --- |
| COMMON | FONT.BIN, SFX.BIN, SPRITES.BIN, UI.BIN, WORLDINF.BIN | Resident font, PSG effects, core sprites/masks, menus and compressed world descriptions |
| TITLE | GFX.BIN, MSX.BIN | Normal/crowned title and music |
| INTRO / OUTRO | GFX.BIN, MSX.BIN | Cutscene pictures and music |
| CREDITS | GFX.BIN | Credits pictures |
| ENDING | MSX.BIN | End-game music |
| WORLD0..WORLD5 | GFX.BIN, MAPS.BIN, SPRITES.BIN, optionally MSX.BIN | Backgrounds/tiles, levels/collisions, world sprites, music |

WORLD5 has no separate music stream in the existing game. Title, achievements
and the complete selector remain resident. There are 698 unique
arrays/font, 982652 unique payload bytes, now split into 36 bundle files.
Including shared sprite copies: 706 stored entries, 997092 payload bytes.
The generated manifest is authoritative after artwork changes.

### Sprite bundles

World membership comes from the game's generated SetupWorldSpriteAtlas table,
not a guessed filename or only the currently visible room. Each world includes
every sprite that its dispatch table can select, including animation data.
Unmapped exports and missing mapped graphics stop generation with an error.

These are expanded payload sizes (RAM), not compressed disk sizes:

| File | Expanded bytes |
| --- | ---: |
| COMMON/SPRITES.BIN | 40456 |
| WORLD0/SPRITES.BIN | 37040 |
| WORLD1/SPRITES.BIN | 38000 |
| WORLD2/SPRITES.BIN | 36920 |
| WORLD3/SPRITES.BIN | 37680 |
| WORLD4/SPRITES.BIN | 33520 |
| WORLD5/SPRITES.BIN | 32200 |

COMMON holds Flob, small slime, explosion and particle layers, including their
EMS masks/offsets. The four shared world-sprite families are copied into each
world using them: bigslime (all six), birdpoop (2/4), bat (3/4), drop (3/5).
Copies add 14440 expanded payload bytes before compression, but let each world's bundle stand alone
without retaining an all-world shared sprite pool later. Copies have identical
hashes and each has its own offset in its bundle. Manifest fields `worlds`,
`resident_core`, `shared_sprites` and stored/unique totals describe this explicitly.

Only COMMON and the active world's sprites reside in RAM. When switching worlds,
the old blocks are freed before allocating the new ones. Shared sprite variables
are rebound to the new owner, and sprite histories and pointer tables are reset.

Host partition checks: `python3 -m unittest test_file_sprite_groups.py`.

## Format and validation

Payloads retain existing compression and ST big-endian words. No runtime graphic
conversion. The 24-byte header contains magic FLB2, u16 version=2, u16 entry
count, u32 expanded length, u32 expanded CRC32, u32 stored length and u32
stored CRC32, all big-endian. A shorter stored length indicates an Apultra
stream; equal lengths indicate raw data (compression did not help). Every array
starts at an even offset; odd payloads have one padding byte.

Compressed input uses a temporary allocation, freed immediately after UnApl.
The final expanded data uses one allocation per bundle; generated bindings point typed
Pascal array pointers at even offsets inside that allocation. Runtime pointer
tables are refreshed after load/release. The loader checks open/read/close
errors, exact size, version/fingerprint and entry count. Generated compile-time
checks compare each Pascal array type's size against its exported payload.
Failure restores
input, sound and video, frees loaded blocks, and reports the failing path.

Every build validates the stored payload CRC before invoking UnApl and validates
the expanded CRC afterwards. Header fields must match compiled fingerprints.
Manifest asset offsets describe the expanded layout plus the 24-byte header,
not seek positions within compressed files. VERIFY_FILE_ASSETS checks bundles
on the emulated 68000 and writes LOAD.OK or FILE.ERR. The test harness uses
private disk copies, including missing/truncated/corrupted-file tests.

Relocatable pointer tables, sprite frame/tile descriptors, achievement rules
and program text remain compiled metadata. Literal graphics, palettes, fonts,
compressed world/collision data, PSG and packed FYM streams are external.
DMA is not included. Unsupported non-literal array values cause export failure.

## Ownership and transitions

- COMMON and TITLE are pinned for the program lifetime: 150578 payload bytes.
- WORLDINF holds six compressed world descriptions (22982 bytes), not graphics.
  Selector, achievements and stats use an 8192-byte scratch buffer and never
  load a world's graphics/sprites. Gameplay has its separate world-data buffer.
- Gameplay loads only the selected world's GFX, MAPS and SPRITES. No disk reads
  occur when moving between rooms or during reveal within that world.
- Intro/outro load GFX on entry and free it after completion or skipping.
- Credits load only on demand and are freed on exit, not kept permanently.
- Only the selected compressed song is retained, apart from pinned title music.
  PSG plays the independent decompressed musicBuffer, so freeing compressed
  outro music does not interrupt the following credits.
- The hardware palette is checked before every resource read. Setpalette is
  asynchronous: wait for VBL before assuming black has reached the registers.
  A requested song load during gameplay saves the actual palette, fades out,
  loads, then restores it. A stack-local palette must be latched before return.

Canonical loader sources are `dynamic_file_resources.py`,
`file_resource_runtime.inc` and `file_resource_verify.inc`. The generator injects
lifetime hooks only into the staged copy of flob.pas. The old
`file_loader.template.inc` is the historical preload loader, no longer used.

## Verification, 2026-10-12

- Standard ST and auto-detect ST/STE file-backed builds compiled successfully.
- Target CRC verification passed for all 698 assets.
- Missing and truncated bundles are rejected with cleanup of initialized video.
- Deliberate same-size payload corruption was caught by verification CRC.
- File-backed ST and STE gameplay regressions passed at 1 MB: sprite queues and both-page
  histories, overlaps, occlusion, flips, collision/trigger and input tests.
- Target CRC tests passed on STE with 1 MB: two allocation/free cycles,
  every read black, resident resources 150578 bytes, peak 294900 resource bytes.
  Largest free GEMDOS block after resident loading was about 298 KiB (test PRG).
- Rendered lifetime tests passed on both ST and STE with 1 MB: six worlds,
  selector/title, intro/outro/credits and live song switching, twice without
  leaking or fragmenting the remaining GEMDOS block. Peak resource storage with
  all song selections was 304132 bytes, about 297 KiB. BSS fell from 1072052 to
  104356 bytes before the packed-loader additions. These are separate from three screen
  allocations, stack/heap and TOS. See `reports/file_assets_*`.
- Missing world graphics and truncated intro graphics after hardware/input/audio
  initialization were rejected through the same cleanup path.
- Full-game manual playtesting and physical ST/STE testing remain outstanding.

### Packed floppy verification

`verify_floppy.py` runs private copies of actual 720 KiB images, with no HDD,
1 MiB RAM, 68000 at 8 MHz, configured TOS and normal FDC timing (fastfdc off).
CRC, rendered resource-lifetime and gameplay regression tests pass on both ST
without blitter and STE. Reports are read back from FAT12, not a host directory:
`reports/floppy_{crc,lifetime,gameplay}_{st,ste}.txt`.
Peak resource allocation including compressed-input scratch is 304132 bytes;
the largest free GEMDOS block after resident loading is 301284 bytes in the
lifetime test. The unmodified release also reaches title, selector, intro and
the first room, with movement and flip tested on both machines.

The current release PRG is 56644 bytes (134936 before UPX). The complete image
has 37 files and 13312 bytes free, including room for FLOB.SAV. Exact budgets
and hashes are written to `FLOB720.json`; build failure prevents publishing an
image that cannot fit or leaves less than 1 KiB for saves. All files are read
back and compared after image creation. Real floppy loading can keep the
screen black for several seconds; smoke tests wait for visible scenes rather
than assuming HDD-like load times.

## Remaining validation

Play all worlds from this distribution at 1 MB, including death, reveal, secret
rooms, statistics, skips, game over and outro-to-credits continuity. Check slow
physical media and different TOS/accessory memory footprints; emulator free RAM
is not a guarantee for every real machine configuration. Further deduplication
could increase the small remaining disk-space margin for future artwork.
